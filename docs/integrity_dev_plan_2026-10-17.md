## 2. P0-2 결재 ✅ → rules.txt 반영 현황 (설계)
- rules.txt 맨 위에 생성 블록(사람이 안 고침):
  ```
  # [결재 반영 현황 — 자동 생성, scripts/rules_status.py] 기준 <원장 최종 갱신>
  # 결재#  조항     상태      원장 키
  # #2     [5]      미반영    7-1
  # #3     [3],[11] 미반영    7-3
  ```
- 입력: 원장 §7-3 결재 줄(결재 # → 조항 [n] 매핑은 원장 문구의 `[n]` 토큰), rules.txt 조항 본문의 `(결재 #n 반영 m/d)` 꼬리표. 꼬리표 없는 ✅ 결재 = 미반영.
- integrity_check (g) 추가: 미반영 결재가 **발효일 + 7일** 지나면 중, 예약 PB 가 읽는 조항([5]·[12])이면 치명.
- 순서: 월 장 후 → 블록 생성기 + 테스트 → 일요일 결재에서 본문 개정(오너) → 꼬리표 부착. 본문 문구는 개발이 쓰지 않는다.
- **구현(10/26 저녁, 개발):** `scripts/rules_status.py` — 미리보기 / `--write`(맨 위 블록만 교체, 본문이 바뀌면 중단) / `--check`(종료코드 1 = 치명). 경로는 `--pb`(기본 `../pb-private`). 출력 = 결재 번호·조항 번호·상태·원장 키만.
  - 상태: 반영 · 일부 반영 · 미반영 · 조항 없음(rules.txt 에 [k] 헤더 없음) · 미지정(원장에 [k] 토큰 없음) · 규정 무관(원장 줄에 '(규정 무관)') · 통합→#b.
  - 매핑: §7-3 `- #n …`(한 줄 `· #m` 여러 건) 의 `[k]` + 원장 ✅ 줄의 `결재 #n [k]`. 발효일 = §7-3 헤더 날짜(줄에 `(m/d 발효)` 있으면 그것).
  - 검사: 발효+7일 지난 미반영·일부·조항 없음 = 중, [5]·[12] = 치명 / 미지정·블록 낡음 = 경. `pb:` integrity_check (g) `G-rules` 가 같은 함수를 씀(`--no-rules` 로 생략).
  - 테스트: `tests/test_rules_status.py` 7건(가짜 원장·규정) + `pb:` test_integrity_check (g) 1건.
  - 10/26 실데이터: 도장 결재 13건 중 통합 3 · 미지정 9 · 조항 없음 1(#4 → [13], rules.txt 에 [13] 없음 = 중). 치명 0 — 단 #2·#3 등은 원장에 조항 토큰이 없어 '미지정'이라 미반영 여부를 아직 못 잼. 다음: 기록 데스크가 §7-3 줄에 [k] 또는 '(규정 무관)' 표기.
