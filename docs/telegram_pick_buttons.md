# 텔레그램 '내 선택은?' 버튼 켜기 (겸이용 배포 절차)

보드 `tg-pick-buttons` · 2026-10-20 · 개발 데스크

## 무엇이 바뀌나

- 대결 메시지(14:55 국장 대결 · 22:00 미장 대결 · PB 판단) 아래에 **버튼**이 붙는다: `KODEX 200 · 레버리지 · 인버스` / `현금 · ✍️ 직접 입력 안내` (미장은 `SPY · QQQ · SOXX · SQQQ`).
- 버튼을 누르면 → 텔레그램이 구글 앱스 스크립트 웹앱(`apps-script/TelegramHook.gs`)을 부르고 → 웹앱이 겸이 깃허브 토큰으로 `pick 2026-10-21` 이슈를 대신 연다 → 지금까지 쓰던 `pick.yml` 이 그대로 기록한다.
- 1~2분 뒤 텔레그램으로 **반영 결과**(기록 완료 / 마감 지남 / 쿨다운)가 온다.
- 채팅에 `pick 005930 시가` · `pick 현금` · `pick-us QQQ 5일` 처럼 직접 써도 같은 길로 기록된다.
- 채팅에 `ask <데스크> <내용>`(예: `ask 퀀트 accum 백필 언제 돼?`) → `ask 퀀트` 이슈 → `ask.yml` 이 요청 장부(`docs/desk_kb/rounds/_requests.json`)에 from=겸이로 추가하고 닫는다. 결과는 매일 00:07 watchdog 요약의 '📮 사내 메신저' 절(10/21).
- 기존 링크는 버튼이 안 될 때를 위한 보조로 그대로 남아 있다.

설정 전까지는 버튼을 눌러도 아무 반응이 없다(메시지 전송에는 영향 없음).

## 준비물 확인 (1회)

1. **텔레그램 다른 곳이 봇 업데이트를 읽고 있지 않은지** — 저장소 2곳(market-screener · pb-private)에는 `getUpdates`·`setWebhook` 을 쓰는 코드가 없다(10/20 확인). 다른 곳(노트북 스크립트 등)에서 이 봇으로 `getUpdates` 를 돌리고 있다면, 웹훅을 걸면 그쪽이 멈춘다. 그런 게 없다면 그냥 진행.
2. **깃허브 토큰에 이슈 쓰기 권한 추가** — 예약 실행기(Scheduler.gs)가 쓰는 `GH_TOKEN` 은 지금 *Actions 읽기/쓰기* 만 있다.
   - GitHub → Settings → Developer settings → Fine-grained tokens → 그 토큰 → Edit → Repository permissions → **Issues: Read and write** 추가 → Save.
   - 꼭 **저장소 주인 계정(hk99915-bot)으로 만든 토큰**이어야 한다. `pick.yml` 은 "저장소 주인이 연 이슈만" 기록하기 때문(이 조건은 일부러 그대로 둔다 — 아무나 이슈로 기록하지 못하게).
   - 권한을 섞기 싫으면 이슈 전용 토큰을 새로 만들어(Issues: Read and write 만) 스크립트 속성 `GH_ISSUE_TOKEN` 에 넣는다. 있으면 이쪽이 먼저 쓰인다.
3. **내 텔레그램 사용자 id** — 봇과의 1:1 채팅 id 와 같다. 깃허브 시크릿 `TELEGRAM_CHAT_ID` 에 넣은 값이 1:1 채팅이면 그 숫자. (그룹방이면 `-100…` 으로 시작하니 그건 아님 — 이때는 텔레그램 `@userinfobot` 에 말을 걸어 나오는 숫자 id.)

> 토큰·비밀값은 **채팅(PB 포함)에 붙이지 말 것.** 아래는 전부 구글 스크립트 편집기 화면 안에서만 넣는다.

## 1. 코드 넣기

1. script.google.com → **예약 실행기 프로젝트**(Scheduler.gs 가 있는 것) 열기. (터미널 웹앱 프로젝트는 '나만 접근' 이라 텔레그램이 부를 수 없어 안 됨.)
2. 파일 `+` → 스크립트 → 이름 `TelegramHook` → 저장소의 `apps-script/TelegramHook.gs` 내용을 통째로 붙여넣기 → 저장.
   - 이 프로젝트에 `doPost` 가 이미 있으면 안 된다(현재 없음). 이름은 모두 `tg` 로 시작해서 Scheduler.gs 와 겹치지 않는다.

## 2. 스크립트 속성 넣기

프로젝트 설정(톱니) → 스크립트 속성 → 속성 추가:

| 이름 | 값 |
|---|---|
| `TG_BOT_TOKEN` | 텔레그램 봇 토큰 (BotFather 에서 받은 것 — 깃허브 시크릿 `TELEGRAM_TOKEN` 과 같은 값) |
| `TG_WEBHOOK_SECRET` | 아무 긴 임의 문자열. **영문·숫자·`_`·`-` 만**, 30자 이상 권장 (예: 비밀번호 생성기에서 기호 빼고) |
| `TG_OWNER_CHAT_ID` | 위 준비물 3의 숫자 |
| `GH_TOKEN` | (이미 있음) 준비물 2에서 권한만 추가 |
| `GH_ISSUE_TOKEN` | (선택) 이슈 전용 토큰을 따로 만들었을 때만 |

## 3. 웹앱으로 배포

1. 오른쪽 위 **배포 → 새 배포** → 유형 톱니 → **웹 앱**.
2. 설명: `telegram hook` · 실행 사용자: **나** · 액세스 권한: **모든 사용자** (텔레그램 서버가 로그인 없이 불러야 해서. 대신 비밀값·주인 id 를 안 맞으면 아무것도 안 한다).
3. 배포 → 권한 허용 → 나오는 **웹 앱 URL**(`https://script.google.com/macros/s/…/exec`) 복사.
4. 스크립트 속성에 `TG_WEBHOOK_URL` = 그 URL 추가.

코드를 고친 뒤엔 **배포 관리 → 기존 배포 연필 → 버전: 새 버전 → 배포** (URL 이 안 바뀌어 웹훅을 다시 걸 필요 없음). '새 배포'를 또 만들면 URL 이 바뀌니 주의.

## 4. 웹훅 걸기 (1회)

편집기 위쪽 함수 선택에서 **`tgSetWebhook`** → 실행. 로그에 `{"ok":true,"result":true,"description":"Webhook was set"}` 이 나오면 끝.
(토큰을 브라우저 주소창이나 채팅에 붙여 `setWebhook` 을 부를 필요 없다 — 함수가 스크립트 속성에서 읽는다. 비밀값은 URL 의 `?s=` 와 `secret_token` 둘 다에 들어간다. 구글 웹앱은 요청 헤더를 못 읽어서 실제 확인은 `?s=` 로 한다.)

## 5. 테스트

1. 함수 **`tgWebhookInfo`** 실행 → 로그에 `url_set: true`, `last_error` 가 비어 있으면 정상.
2. 텔레그램 봇 채팅에 `pick 현금` 을 보낸다 → 바로 "기록 접수 ✅ pick 2026-…" 답장 → 1~2분 뒤 "🎯 pick 2026-… 기록 완료 ✅ … 나: 현금".
   - 15:30 이후에 하면 "15:30 KST 이후 제출이라 반영하지 않았어" 가 온다(정상 — 마감 확인까지 된 것).
   - 깃허브 저장소 Issues(닫힌 것)에 `pick 날짜` 이슈가 생기고 봇 답글이 달려 있으면 끝까지 성공.
3. 다음 대결 메시지에서 버튼을 눌러 본다. 같은 버튼을 10분 안에 또 누르면 "이미 접수됨" 이 뜬다. 다른 버튼을 누르면 마지막 선택이 남는다.

**안 될 때**
- 답장이 전혀 없음 → `tgWebhookInfo` 의 `last_error` 확인. `Wrong response … 302` 류가 보여도 기록이 되면 무시해도 된다(구글 웹앱 특성; 같은 요청 재전송은 10분 중복 방지로 한 번만 처리). 기록도 안 되면 편집기 왼쪽 **실행** 메뉴에서 doPost 로그 확인.
- "기록 실패 ❌ GitHub 403/404" → 준비물 2(Issues 쓰기 권한, 저장소 선택) 확인.
- "접수"는 왔는데 결과 알림이 안 옴 → 깃허브 Actions 의 `pick` 실행 확인. 이슈 작성자가 저장소 주인이 아니면 `pick.yml` 이 건너뛴다(토큰이 다른 계정 것).

## 롤백

- 편집기에서 **`tgDeleteWebhook`** 실행 → 웹훅 해제. 버튼은 눌러도 반응이 없어지고, 메시지의 링크(노트북 브라우저)로 제출하면 된다.
- 완전히 빼려면 웹앱 배포 보관 처리(배포 관리 → 보관) + 저장소에서 이 기능 커밋 revert(버튼이 메시지에서 사라짐).

## 보안 메모

- 처리 조건: ① URL 비밀값 일치 ② 누른 사람 id == `TG_OWNER_CHAT_ID`. 둘 중 하나라도 아니면 아무 동작 없이 끝난다.
- 이슈는 주인 토큰으로 열리므로 `pick.yml` 의 "저장소 주인만" 조건을 넓히지 않았다.
- 버튼 데이터 형식: `p|날짜|K/U|종목|청산` (64바이트 이내) — 파이썬 `screener/duel.py pick_cb`/`parse_pick_cb` 와 GAS `tgParseCallback_` 이 같은 규칙이고 `tests/test_tg_pick_buttons.py` 가 node 로 두 쪽을 대조한다.

## 폴링 모드 (10/21 02시 — 웹훅 302 문제)
GAS 웹앱 응답은 항상 302 리다이렉트라 텔레그램이 웹훅을 '실패'로 보고 재시도·백오프한다(getWebhookInfo `last_error: Wrong response from the webhook: 302 Found`, `pending` 증가 → 답장이 수십 분 늦거나 같은 pick 이 여러 번). 그래서 **1분 시간 트리거 `tgPoll` 이 getUpdates 로 가져오는 방식**으로 바꾼다.
1. TelegramHook.gs 새 코드 붙여넣기 → 저장 → 배포 관리 → 새 버전 배포.
2. 편집기 함수 선택 `tgInstallPolling` → ▶ 실행 (권한 요청 뜨면 허용 — 트리거 생성 권한). 로그에 `폴링 설치 완료` 와 `"url":""` 가 보이면 끝.
3. 텔레그램에 `ask 운영 테스트` → 1분 안에 '📮 요청 접수' 답장.
되돌리기: `tgUninstallPolling` → `tgSetWebhook`. 지연: 최대 1분(버튼 누른 뒤 '로딩' 표시가 잠깐 남을 수 있음).
