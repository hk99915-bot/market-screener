### 결정 B — 데이터 계약 (A와 무관하게 필수, 추천)
- 산출물마다 `schema_version` + 필수 키 목록(작은 dict 스키마)을 `screener/contracts.py`에 두고, 쓰기 직전 검사 → 위반 시 쓰지 않고 로그. 테스트가 같은 스키마로 검사.
- **asof 단조 가드**: 새 asof < 기존 asof 이면 그 파일은 덮어쓰지 않음(보드 detail-us-regress). 모든 상세·요약 쓰기 함수 공통 1곳.
- 정의 단일 원천: 분모·한도·기한 상수를 `screener/defs.py` 한 곳에(rules_terms.md 와 이름 일치 검사 — 기존 check_rules_terms 확장).
- 피저빌리티 **상** — 반나절, 기존 코드 동작 불변(검사만 추가), 롤백 쉬움.

### 결정 C — 예약 일원화
- 원칙: **산출물 하나 = 실행 주체 하나**. GitHub cron 이 밀리는 슬롯만 GAS 가 dispatch 하고, 같은 슬롯 cron 은 끔(지금은 둘 다 + 수동). 수동 dispatch 는 "읽기 전용 모드(no-commit)" 기본.
- 피저빌리티 **상** — 표 한 장 + 워크플로 조건 몇 줄. 단, GAS 쪽은 오너 붙여넣기 1회 필요.

### 결정 D — 코드 구조 (일요일엔 하지 않음, 11월 Pro 전 착수 후보)
- committee.py 를 블록별(매크로·수급·아이디어·실행·텔레그램) 모듈로, main.py 모드 → 레지스트리 dict. 피저빌리티 중, 위험 중(가장 많이 읽히는 파일). **데이터 계약(B)이 먼저 있어야 안전하게 쪼갤 수 있음.**
