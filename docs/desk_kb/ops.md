# 운영 데스크 KB

운영 = 여러 에이전트가 한 저장소를 동시에 고치는 환경의 **보드·잠금·예약·수집** 담당 (코디네이터 보조). 판단을 내는 데스크가 아니라 판단이 흐르는 길을 관리한다.
개인 보유·금액 없음. 출처 등급: `[교과서]` `[논문]` `[규정]` `[자체연구-A/B/C/F/검증전]` `[경험]`.

## 정의
- **라운드**: LOOP.md 5항목(읽기·배움·고침·피어·복기) + 마지막 줄 `요청→<데스크>: …`. 파일 `docs/desk_kb/rounds/YYYY-MM-DD/<desk>.md`.
- **요청 장부**: `docs/desk_kb/rounds/_requests.json` — `scripts/round_collect.py` 가 관리. 요청은 대상 데스크가 자기 라운드 파일에 `처리→<요청 데스크>: …` 를 쓸 때 닫힌다. 2라운드 연속 미처리 → 보드 P1 '대기' 승격(기본 드라이런, `--apply` 로 반영).
- **슬롯**: 워크플로 cron 한 줄 = 슬롯 하나. 모드는 실행 시각이 아니라 **어느 cron 이 울렸나**로 정한다(briefing.yml '모드 결정').

## 보드 운영
- 원본 `ops/board.json`, 판 `ops/BOARD.md` (`python3 scripts/board.py`). 필드: id·title·**owner**(담당 이름, 'desk' 아님)·priority P0~P3·status(대기/진행/검수/보류/완료)·started·due·repo·files·depends_on·notes. 검증 `--check`.
- 잠금: 공유 파일(LOCKS.md 표)만, 파일 하나가 단위, 작은 커밋으로 즉시 푸시. 남의 잠금 안 지움.
- 라운드 수집: `python3 scripts/round_collect.py --date D` (드라이런) → 출력 확인 → `--apply` → 보드가 바뀌었으면 `board.py --check` → 커밋. 모든 데스크가 라운드 파일을 다 쓴 뒤(21:10 라운드면 23:47 ops 전)에 돌린다.

## 현업 vs 교과서
- `[규정]` GitHub Docs "Events that trigger workflows › schedule": 예약 워크플로는 부하가 높은 시간대에 지연·누락될 수 있고 **매시 정각이 가장 밀린다**, 최소 간격 5분, 기본 브랜치의 최신 커밋 기준으로 돈다. → 우리 cron 이 :52·:47 같은 비정각인 이유. 지연이 수십 분일 수 있어 모드를 '시각'이 아니라 'cron 문자열'로 정한 것도 같은 근거.
- `[경험]` 그래도 누락은 남는다 → GAS 백업 예약기(dispatch)로 이중화. 중복은 '먼저 온 쪽이 이김'으로 푼다.

## 흔한 오해
- "라운드 표를 손으로 _scoreboard.md 에 적는다" → 아니다. 수집 스크립트만 적는다(중복 줄 방지: 같은 라운드·데스크는 다시 안 붙임).
- "요청은 적으면 처리된 것" → 아니다. 대상 데스크의 `처리→` 줄이 있어야 닫힌다. 없으면 2라운드 뒤 P1.

## 우리 연구와의 차이
- 없음(운영은 연구 데스크가 아님). 데스크 성적과 라운드 표의 상관은 월 1회 코디네이터가 본다(LOOP.md).
