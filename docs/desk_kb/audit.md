# audit(감사) 데스크 KB — slop 감사 기준서

(2026-10-17 신설. 오너 지시 "slop 감사팀 신설, 완전 실무적으로, 실제 현업급". 형식은 README.md. 공개 저장소 — 금액·보유 없음.)
역할: 모든 데스크 산출물(PB 포함)을 아래 기준으로 **채점**한다. 수정은 하지 않고 요청한다(피어 구조) — 예외는 §3 (e) 하나뿐.
도구: `python3 scripts/slop_audit.py` (자동 항목) → `reports/audit/YYYY-MM-DD.{md,json}`. 수동 항목은 감사 데스크가 같은 표에 직접 적는다.

## 성격·성향
- **한 줄:** 모순을 파일·행 번호로 특정하고 고치지는 않는 무편집 지적자(문언 우선·출처 판정 엄격).
- **맹점:** 첫 자동 실행 오탐 95%(복기 10/17)·로그 파일 실명 미탐(복기 10/21). **긴장:** ↔PB — VOC 출처를 'PB추정'으로 판정. 원본 [PERSONAS.md#audit](PERSONAS.md#audit)(요약, 연기 지시 아님).

## 1. 정의 — slop
- **slop** = 읽는 사람의 판단을 돕지 않으면서 자리를 차지하는 문장·숫자·코드. 내부감사 기준으로는 "근거 추적(traceability)이 끊긴 산출물". 산출물 하나에 slop 1건이면 그 산출물 전체의 신뢰가 깎인다 — 그래서 건수가 아니라 **최고 심각도**로 산출물 등급을 매긴다. `[현업 관행: 내부감사 3선 모델의 2선(통제) 역할 — 1선(데스크)이 고치고 2선이 채점, 3선(오너)이 결정]`
- 심각도: **치명** = 공개돼서는 안 되는 것이 공개됐거나, 틀린 숫자가 결정에 쓰일 수 있는 상태 / **중** = 근거가 끊겨 독자가 검증할 수 없는 상태 / **경** = 형식·표기 — 읽기 비용만 올리는 것.
- 조치 기한: 치명 **당일**(발견 즉시 보드 P0) · 중 **3일** · 경 **7일**(다음 라운드까지). 기한 지난 중은 보드 P1로 승격(ops `round_collect` 규약과 동일).

## 3. 절차
1. 라운드 종료 후 `python3 scripts/slop_audit.py` 실행 → 자동 표. 종료코드 1(치명)이면 그 자리에서 멈추고 (e)·(h) 부터 본다.
2. 수동 항목은 **산출물별로 전체를 읽고** 표에 추가한다 — 자동 표만 복사하면 그것이 slop 이다. 산출물당 수동 소요 상한 10분.
3. 치명 → 보드 P0(담당 = 해당 데스크, notes 앞에 '감사 지적'). 중·경 → 라운드 파일 `요청→<데스크>:` 로 보낸다. 같은 지적이 2라운드 연속이면 P1.
4. **유일한 직접 수정 예외**: (e) 개인 금액이 공개 저장소에 있으면 그 줄만 비율·단위로 치환하고 커밋 메시지에 `감사: 금액 누출 제거` 를 적는다. 다른 줄은 손대지 않는다. (공개 이력에는 남으므로 PB 에게 이력 정리 여부를 보고한다.)
5. 채점표 형식: `| 산출물 | 항목 | 심각도 | 근거(파일:줄) | 조치 | 기한 |`. 근거는 **줄 번호까지** — 줄 번호 없는 지적은 감사 자신의 (a) 위반이다.
6. 감사 데스크 산출물도 다음 라운드 감사 대상이다(자기 면제 없음). 감사 지적에 대한 반론은 대상 데스크 라운드 파일 `처리→audit:` 1줄로 받고, 다툼은 KB '차이'에 양쪽을 적고 오너 결정.

## 4. 공식 (쉬운 숫자)
- 산출물 등급 = 최고 심각도. 치명 1 + 경 10 → 치명. 경 10 만 → 경. 건수는 추세용(라운드 표 '감사' 열: 치명/중/경).
- 자동 탐지 오탐률 목표 ≤ 20% (허용 목록으로 조정). 미탐은 수동 채점에서 잡히는 비율로 월 1회 측정 — 자동이 못 잡은 치명이 1건이라도 있으면 그 주에 정규식을 고친다.
- `[확인 필요]` 나이 = 오늘 − max(파일명 날짜, 본문 최신 날짜) — git blame 대신 쓰는 근사. 파일에 날짜가 하나도 없으면 mtime(체크아웃 시각이라 과소 추정됨 — 경고만).

## 5. 현업 vs 교과서
- 내부감사 교과서(IIA 3선 모델)는 2선이 통제를 **설계·감시**하고 1선이 고친다. 우리도 같다 — 감사가 직접 고치면 독립성이 깨지고, 고친 사람이 채점하는 순환이 생긴다. (e) 예외만 두는 이유: 공개 저장소의 금액 누출은 시간이 피해를 키우는 유일한 항목. `[현업 관행]`
- 교과서 샘플링(통계적 표본)은 쓰지 않는다 — 산출물이 하루 20개 안쪽이라 **전수**. 전수가 안 되는 날은 (e)(h)(i) 치명 후보만 전수, 나머지는 라운드 파일 우선.

## 6. 흔한 오해
- "자동 표가 비어 있으면 통과" ✕ — (a)(h)(i)(j)는 자동이 못 본다. 자동은 하한선.
- "치명 = 데스크 징계" ✕ — 치명은 **공개 범위 사고**다. 사람이 아니라 경로(어느 파일에서 어떤 문장이 새는가)를 고친다.
- "검증전 이라고 적었으니 끝" ✕ — 꼬리표가 있어도 같은 문단에서 "그래서 X 하면 된다" 로 결론 내리면 (b).
- "모의 대결 금액은 개인 금액이 아니다" △ — 고정 사이즈라도 문장에 '모의' 가 없으면 독자는 실제 금액으로 읽는다. 단위(1단위·비율)로 쓴다.

## 7. 터미널에서 보는 자리
- `reports/audit/<date>.md` 채점표 · `<date>.json` (`counts`·`by_desk`·`findings[]`, ops `round_collect` 가 `by_desk` 를 읽어 라운드 표 '감사' 열에 씀).
