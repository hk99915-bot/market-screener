## 정의
1. [경험] 기록 데스크가 쓰는 원장 세 가지: ① **일기**(하루의 '마음의 타임라인' — 겸이 실제 말 짧은 인용 · PB 대응 · 결과, 그리고 '패턴 메모') ② **운용 히스토리**(결정·실행·결과, 월 파일) ③ **합의 원장**(✅시행 / 🗳️일요일 상정 / 🔒약속). 새 세션은 합의 원장부터 읽는다.
2. [규정] **발언과 해석의 분리**: 원장·일기에는 겸이의 말(인용)과 PB가 덧붙인 해석을 다른 칸·다른 표기로 적는다. 근거: pb-private 상시 규칙 '답변 전 확인 원칙' 5항, 사례 = HANDOFF 복기 16호(주말 원칙에 PB 문구가 덧붙어 원칙처럼 기록됨).
3. [규정] **데스크 발언(VOC)은 실제 데스크 보고만 인용**한다. 판정 기준(VOC 재검증, 2026-10-17): 그 시각 이전에 해당 데스크 에이전트가 낸 보고에 같은 내용이 있으면 '실제보고', 에이전트 실행 전·미실행·PB 작업을 데스크 말로 쓴 줄은 'PB추정'. **결과가 나중에 맞아도 출처는 바뀌지 않는다.**
4. [교과서] 의사록(minutes)은 원칙적으로 "무엇을 했는가(결정)"의 기록이지 "누가 무엇을 말했는가"의 기록이 아니다(Robert's Rules of Order). 우리는 여기에 **결정 직전 겸이의 한 줄 인용**을 붙인다 — 결정이 어떤 상태에서 나왔는지(밤·보상 직후 등)가 행동 진단의 재료이기 때문이다.
5. [경험] **무편집 인용**: 인용은 오탈자·줄임말까지 원문 그대로. 고친 인용은 인용이 아니라 해석이다.

## 공식
6. [경험] 기록 지연 = 원장 기록 시각 − 결정 시각. 22:00 이후 결정 금지 규칙을 판정하려면 **결정 시각(분 단위)** 이 원장에 있어야 한다 — 날짜만 있는 ✅는 22시 전후를 가릴 수 없다(기록 데스크 10/16 발언).
7. [경험] 기록률 = 원장에 반영된 결정 수 / 대화에서 나온 결정 수. 결정 1건 = (무엇을 · 누가 · 언제까지) 세 칸이 다 찬 것. 하나라도 비면 '결정 후보'로 🗳️에 둔다.

## 현업 vs 교과서
8. [교과서 vs 경험] 이사회 의사록 관행은 발언 요약을 최소화한다(분쟁 시 해석 다툼 방지). 우리는 반대로 **짧은 원문 인용**을 남긴다 — 목적이 법적 증빙이 아니라 행동 복기(재협상 횟수·밤 결정·보상 직후 결정)이기 때문. 대신 인용과 해석을 표기로 분리한다(#2).
9. [경험] 실행 확인 칸: 결정(지정가 주문 등) 옆에 체결/미체결/취소 칸을 둔다. 없으면 다음 날 "체결됐어?"를 다시 물어야 한다(기록 데스크 10/16 애로 3).

## 흔한 오해
10. [경험] "요약이 인용보다 깔끔하다" → 요약은 기록자의 해석을 섞는다. 요약을 쓰면 '(요약, 기록자)'를 붙인다.
11. [경험] "PB가 대화 중에 적었으니 기록은 끝났다" → PB 기록은 바쁜 시간에 빠진다. 기록 데스크는 커서 이후 대화 전체를 다시 훑어 빠진 합의를 잡는 **두 번째 눈**이다.
12. [경험] "(PB 추정)이라고 표시하면 데스크 발언으로 써도 된다" ✕ — 2026-10-17 겸이 지시로 금지. 데스크를 호출하지 않았으면 'VOC: 이번 답변은 데스크 미호출'이라고만 쓴다.

## 터미널에서 보는 자리
13. 공개 저장소에는 기록 원본이 없다(비공개 전용). 공개 쪽 흔적: 팀 사용량 `ops/team.json`(기록 `scripts/team_run.py`), 데스크 성격 프로필 `docs/desk_kb/PERSONAS.md`(이 데스크가 관리). 비공개 쪽: 일기·히스토리·합의 원장, 추출 커서, 매 답변 Stop 훅의 턴·토큰 버퍼.

## 우리 연구와의 차이
14. [경험] 절차(비공개 README 요약): ① 커서 이후 대화를 추출(원문 추출본은 git 제외) ② 기록 에이전트가 일기·히스토리·합의 원장·패턴 메모에 반영 ③ 금지 = 농담·애정 표현·사적 대화(겸이 요청으로 제외), 질병·의료, 계좌번호·토큰 ④ 주기 = 평일 점심 직후·마감 직후·세션 종료 전, 주말은 종료 전 1회. 공개 저장소로 옮길 때는 금액·보유를 비율로 바꾼다.
