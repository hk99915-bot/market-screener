# 데스크 지식 베이스 (KB)

각 데스크가 자문·연구 과정에서 얻은 **재사용 가치가 있는 지식**을 쌓는 곳. 조직도(6본부 + 독립 검증실)는 `ORG.md`, 데스크별 성격·성향(실제 발언 인용 근거)은 `PERSONAS.md`.

| 본부 | 데스크 → KB 파일 |
|---|---|
| 투자전략 | CIO `cio.md` · 자산배분 `allocation.md` · 매크로 `macro.md` · 채권 `bonds.md` · 부동산 `realestate.md` · 헤지펀드 `hf.md`(10/21 신설) |
| 리서치 | 퀀트 `quant.md` · 애널 `analyst.md` · 파생 `derivs.md` · 데이터 `data.md` |
| 리스크 | 리스크(FRM) `frm.md` · 행동 `behavior.md` · 컴플라이언스 `compliance.md`(10/24 신설) · 포지션리스크 `posrisk.md`(10/24 신설) |
| 운영 | PM `pm.md` · 운영 `ops.md` · 개발 `dev.md` · 기록 `scribe.md` · UXUI `uxui.md`(10/21 신설) · 유지보수 `maint.md`(10/21 신설) · 프론트 `front.md`(10/24 신설) |
| 교육 | 교육 `edu.md` · 평가 `eval.md` |
| 생활 | 내무 `household.md` · LIFE `life.md` |
| 독립 검증실 | 검증 `verify.md` · 피어리뷰 `peer.md` · 감사 `audit.md` |
데스크 에이전트는 작업 시작 시 자기 KB(`docs/desk_kb/<desk>.md`)를 먼저 읽고, 끝낼 때 새로 확인한 정의·공식·함정·출처를 추가한다 — 자문에 답할 때마다 실력이 남는 구조.

## 파일
- `<desk>.md` — 데스크별 KB. 섹션: 정의 / 공식(쉬운 숫자 예시) / 현업 vs 교과서 / 흔한 오해 / 터미널에서 보는 자리 / 우리 연구와의 차이 / 출처 / 복기
- 공통 문서: `ORG.md`(조직도) · `PERSONAS.md`(데스크 성격 프로필, 기록 데스크 관리) · `CHARACTERS.md`(누나 캐릭터 시트 — 창작, 판단 근거 아님) · `LOOP.md`(데스크 루프) · `STANDARD.md`(현업급 기준) · `_scoreboard.md`(데스크 성적) · `rounds/`(라운드 기록)
- 2026-10-17 추가 KB 5개: `allocation.md` · `scribe.md` · `eval.md` · `household.md` · `life.md` (기존 산출물에서 일반 지식만, 복기 빈 절)
- 항목마다 **출처 등급** 표기: `[교과서]` `[논문]` `[규정]` `[자체연구-A/B/C/F/검증전]` `[경험]`
- 개인 보유·금액 금지. 비율·일반 예시만.

## 규칙
- 자체연구를 인용할 때는 반드시 등급을 같이 쓴다 (검증전 결과를 확정처럼 쓰지 않는다).
- 교과서와 자체연구가 다르면 '차이' 섹션에 둘 다 적고, 어느 쪽을 왜 따르는지 적는다.
- 교육 데스크는 KB 항목을 모듈 sources[]로 인용한다 (`kb:derivs#basis`).

## 데스크 성장 루프 (2026-10-16)
데스크(에이전트)는 세션마다 새로 깨어나므로, 성장은 **파일에 남긴 것**만큼만 일어난다. 세 겹:

1. **배우기(입력)** — 자문·연구를 맡을 때마다 외부 표준 자료(교과서·논문·규정)를 확인하고 KB에 출처 등급과 함께 적는다. 우리 자체연구와 다르면 '차이'에 둘 다 적는다.
2. **맞히기(검증)** — 데스크가 낸 판단은 전부 채점된다: PB·PB🔥 = 모의 대결(reports/decisions.json tally), CIO 아이디어 = reports/ideas_attrib.json(출처별 적중), 연구 = 등급(A/B/C/F/검증전)과 퀀트-재현의 독립 재현, 관점(렌즈) = scripts/view_attribution.py. 성적은 월 1회 `docs/desk_kb/_scoreboard.md`에 데스크별로 모은다.
3. **고치기(복기)** — 월말(또는 큰 오판 직후) 각 데스크는 KB의 `## 복기` 절에 "틀린 판단 → 왜 → 다음부터 어떻게"를 3줄로 남긴다. 다음 세션의 같은 데스크는 시작 시 KB 전체 + 최근 복기 3건을 읽는다. 같은 실수를 두 번 하면 그 데스크의 자문 가중치를 낮춘다(CIO ideas_top의 출처 가중과 같은 방식).

교차 성장: 퀀트-재현은 모든 데스크 연구를 재현하고, FRM은 CIO 메모를, CIO는 FRM 한도를 서로 검토한다(오늘 10/16 세 데스크가 다른 결론을 낸 것처럼 — 불일치는 버그가 아니라 학습 재료). 교육 데스크는 자문 답변의 품질(출처 유무·등급 표기·예시)을 데스크별로 피드백한다.

## 피어 구조 (2026-10-17 00:30 — 사용자 결정: "후임 구조 말고 다 피어")
데스크는 모두 **동등한 독립 판단 주체**다. '후임·RA·피어'라는 상하 명칭을 없애고 역할로만 부른다.
| 이전 | 지금 | 역할 (누구 밑도 아님) |
|---|---|---|
| 퀀트-데이터 · 애널-RA | **데이터** | 모든 데스크가 쓰는 시세·재무·ETF 구성·캘린더 창고. 커버리지 예산 결정권 |
| 퀀트-재현 | **검증** | 모든 데스크 연구·모델의 독립 재현 (모델 검증팀). 결정 전 재현 선행 원칙, 뒤집을 권한 |
| 교육-후임 | **평가** | 문제은행·SRS·출석·틀린 문제 → KB 환류. 교육과 대등 (설계 vs 평가 분리) |
| 애널-피어 | **피어리뷰** | 애널만이 아니라 **모든 데스크** 산출물의 반대 의견서. 무편집 발행권 |
규칙: 데스크 간 지시 없음, 요청만. 충돌은 KB '차이'에 양쪽 기록 후 PB가 상정, 결정은 사용자. 성장 루프(배우기·맞히기·고치기)는 데스크별로 동일 적용.
