# 데스크 지식 베이스 (KB)

각 데스크(파생·퀀트·리스크·CIO·행동·매크로·채권·애널·교육·개발)가 자문·연구 과정에서 얻은 **재사용 가치가 있는 지식**을 쌓는 곳.
데스크 에이전트는 작업 시작 시 자기 KB(`docs/desk_kb/<desk>.md`)를 먼저 읽고, 끝낼 때 새로 확인한 정의·공식·함정·출처를 추가한다 — 자문에 답할 때마다 실력이 남는 구조.

## 파일
- `<desk>.md` — 데스크별 KB. 섹션: 정의 / 공식(쉬운 숫자 예시) / 현업 vs 교과서 / 흔한 오해 / 터미널에서 보는 자리 / 우리 연구와의 차이 / 출처
- 항목마다 **출처 등급** 표기: `[교과서]` `[논문]` `[규정]` `[자체연구-A/B/C/F/검증전]` `[경험]`
- 개인 보유·금액 금지. 비율·일반 예시만.

## 규칙
- 자체연구를 인용할 때는 반드시 등급을 같이 쓴다 (검증전 결과를 확정처럼 쓰지 않는다).
- 교과서와 자체연구가 다르면 '차이' 섹션에 둘 다 적고, 어느 쪽을 왜 따르는지 적는다.
- 교육 데스크는 KB 항목을 모듈 sources[]로 인용한다 (`kb:derivs#basis`).

## 데스크 성장 루프 (2026-10-16)
데스크(에이전트)는 세션마다 새로 깨어나므로, 성장은 **파일에 남긴 것**만큼만 일어난다. 세 겹:

1. **배우기(입력)** — 자문·연구를 맡을 때마다 외부 표준 자료(교과서·논문·규정)를 확인하고 KB에 출처 등급과 함께 적는다. 우리 자체연구와 다르면 '차이'에 둘 다 적는다.
2. **맞히기(검증)** — 데스크가 낸 판단은 전부 채점된다: PB·PB🔥 = 모의 대결(reports/decisions.json tally), CIO 아이디어 = reports/ideas_attrib.json(출처별 적중), 연구 = 등급(A/B/C/F/검증전)과 퀀트-재현의 독립 재현, 관점(렌즈) = scripts/view_attribution.py. 성적은 월 1회 `docs/desk_kb/_scoreboard.md`에 데스크별로 모은다.
3. **고치기(복기)** — 월말(또는 큰 오판 직후) 각 데스크는 KB의 `## 복기` 절에 "틀린 판단 → 왜 → 다음부터 어떻게"를 3줄로 남긴다. 다음 세션의 같은 데스크는 시작 시 KB 전체 + 최근 복기 3건을 읽는다. 같은 실수를 두 번 하면 그 데스크의 자문 가중치를 낮춘다(CIO ideas_top의 출처 가중과 같은 방식).

교차 성장: 퀀트-재현은 모든 데스크 연구를 재현하고, FRM은 CIO 메모를, CIO는 FRM 한도를 서로 검토한다(오늘 10/16 세 데스크가 다른 결론을 낸 것처럼 — 불일치는 버그가 아니라 학습 재료). 교육 데스크는 자문 답변의 품질(출처 유무·등급 표기·예시)을 데스크별로 피드백한다.
