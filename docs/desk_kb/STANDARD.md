# 현업급 산출물 기준 (오너 지시 2026-10-17: "모든 데스크 완전 실무적으로, 실제 현업급")

감사 데스크는 이 기준으로 채점한다. 못 지키면 산출물이 아니라 초안이다.

## 1. 숫자
- 모든 숫자에 **출처 + 기준일 + 단위**. 예: "PER 11.7 (TTM, 10/16 종가 878.84, SEC 8-K 2026-09)". 출처 없는 숫자는 쓰지 않는다.
- 계산값은 **식과 입력**을 한 줄로 남긴다(검산 가능). 반올림 자리수는 입력의 유효숫자를 넘지 않는다.
- 추정·가정은 `[가정: …]`, 미검증은 `검증전`, 외부 확인 전은 `[확인 필요: 무엇을, 언제까지]` — 기한 없는 '확인 필요' 금지.

## 2. 판단
- 결론은 **행동 가능한 문장**: 무엇을 / 누가 / 언제까지 / 어떤 조건이면 뒤집는가. "모니터링 필요"·"주의 요망"은 결론이 아니다.
- 반대 근거를 최소 1개 같이 쓴다. 없으면 "반대 근거 못 찾음(탐색 범위: …)".
- 등급(A/B/C/F/검증전)·신뢰도(상/중/하)를 붙인다. 등급 없는 자체연구 인용 금지.
- **매매 판단 = trade plan 필수** (10/21 겸이 상시 규칙): 매수·편입·진입을 말하면 진입 구간·스탑·1차/2차 목표·R:R·확률(보정 등급)·E[R]·시간 손절·매크로 필터·컨빅션·크기를 같이 쓴다(`screener/tradeplan.py`, 스펙 `reports/studies/2026-10-21_tradeplan_spec.md`). 계획 없는 '매수/편입' 문구는 생성 금지(tests/test_tradeplan.py).

## 3. 코드
- 변경 = 테스트 + 롤백 방법 + 영향 범위(어느 워크플로·탭·알림이 바뀌나) 한 줄.
- 운영 영향(스케줄·시크릿·알림 소리)은 커밋 메시지에 `[운영]` 꼬리표. 사용자가 해야 할 일이 생기면 보드 `사용자` 태스크로.
- 외부 API·네트워크 실패는 조용히 넘기지 않는다: 로그 + 산출물에 "데이터 없음(원인)".

## 4. 문장
- 한 문장 한 주장. 장식·감탄·반복 금지. 헤지("~일 수 있다")는 불확실성 수치가 있을 때만.
- 경영학 1학년이 읽는다: 비유 → 용어 → 공식 순, 용어 첫 등장에 한 줄 정의.
- 길이 상한: 라운드 파일 40줄, 노트 150줄, 텔레그램 8줄. 넘으면 부록으로.
- **외부 자료(발간물·뉴스·외부 논평)는 링크만 금지** (10/23 겸이 "발간물만 링크로 주지말고, 그 자료의 내용이랑 해석까지… 그사람의 뷰 같은걸 요약해서"): 세 칸 필수 — ① 내용 요약(핵심 주장·숫자 3~5줄) ② 그 사람/기관의 뷰(입장·근거·과거 예측 적중 여부 있으면) ③ 우리 해석(포트·운용회의 함의 + 등급). 재료가 없으면 "요약 재료 없음 — <무엇> 수집 후"라고 쓰고 지어내지 않는다. 원문 대량 복제 금지(요약·짧은 인용만). 저장 형식 `reports/views/digest.json`.

## 5. 보안·규정
- 공개 저장소: 개인 보유·금액·연봉·계좌 0건. 비율만 — 단 **순자산 '목표' 금액은 예외**(10/24 겸이 "목표 금액 ㄱㅊ 앞으로도 이슈 아님"; 실제 보유·잔고 금액은 그대로 금지). 증권사·애널리스트 실명은 리포트 출처 표기(research·analysts·detail)로 허용(10/24 겸이 "애널리스트 실명 ㄱㅊ 앞으로도 이슈 아님"). 매매 지시문 금지(시스템은 신호·근거까지).
- 결정은 오너. 데스크는 추천 + 뒤집힐 조건까지.

## 6. 인수인계
- 라운드 파일 마지막: `VOC:` 1줄(막힌 것·필요한 것) + `요청→<데스크>:` 1줄 + 다음 사람이 5분 안에 이어받을 "현재 상태 3줄".

## 7. 역량 목표 (겸이 2026-10-23 "각 눈나들 역량을 최소 현업 10년차급으루")
- 데스크 역량 목표 = **현업 10년차**. 매주 루프 '배움'(LOOP.md 2항)은 각 KB `## 10년차 기준` 절의 **격차 줄부터** 고르고, 그 절의 드릴을 다음 라운드에서 스스로 풀어 라운드 파일에 답을 적는다. (학습 기준 — 규칙·한도·등급 변경 아님)
- **드릴 형식** (10/24 겸이 결재 G1): KB 엔 문제만(`- 드릴 [<desk>-dN]: …`), 답·채점 키는 `content/drills/<desk>.json`. 라운드 파일에 `드릴: <id> <내 답>` 1줄을 **먼저** 쓰고 그 뒤에 키를 연다. `scripts/round_collect.py` 가 `scripts/drill_grade.py` 로 채점(핵심 숫자·용어 일치율 ≥60% 통과)해 `_scoreboard.md` '드릴 표'에 싣는다. 새 드릴을 KB 에 넣으면 키 파일에 같은 id 를 같이 커밋(`python3 scripts/drill_grade.py --check`, pytest 가 막음).

## 8. 보고 상단 형식 (겸이 10/25 "전부 이런 형식의 보고로 보고형식 맞추기", 10/26 "What so what now what 구조 … 형식통일" · 기준 샘플 `report_format_sample_v3.md` · 보드 `report-format-rollout`)
- **적용**: 상단 요약이 있는 모든 공식 산출물 — 운용회의(국·미)·HF·텔레그램·애널·파생·채권·매크로·부동산·퀀트 연구·데스크 라운드 결론. 사담·1:1·경보 1줄 알림은 제외. 대상 전수·전환 순서 `rounds/2026-10-26/report_format_rollout.md`.
- **칸 정의** (순서 고정, 칸 삭제 금지 — 내용 없으면 `해당 없음(사유)`)
  - **What** (사실·결과): 무엇이 관측·검증·발생했나. 숫자 1개 이상, 해석 금지.
  - **So What** (시사점): 포트·판단에 대한 함의 + 해석상 유의 최소 1개(반대 근거·표본 한계, 2절).
  - **Now What** (조치): 무엇을 / 누가 / 언제까지 / 뒤집힐 조건. 할 일 없으면 `조치 없음(사유)`. 매매 언급 시 trade plan 필수(2절), 실계좌·모의·관찰 꼬리표.
  - **근거 데이터 발췌**: 핵심 지표만 원본 표 그대로(표 ≤8행 또는 불릿 ≤6). 재계산 값은 `(PM 환산)`처럼 계산자 표기.
  - **원본 링크**: 저장소 상대경로 또는 출처 URL 1줄 이상. 원본 없는 요약 금지.
- **배치**: 문서형(연구 요약본) = What → So What → 근거 → Now What → 원본(샘플 v3 순서). 상단형(화면·JSON·텔레그램) = What·So What·Now What 먼저, 근거·원본은 그 아래 또는 링크.
- **문체**: 공식 개조식 — 1줄 1주장 `- ` 불릿, **명사형 종결**(`~확인`·`~유지`·`~불가`·`~필요`), 한자어 중심, 주어 생략. `~습니다`·`~요`·감탄·구어·이모지 금지(신호등 🟢🟡🔴 라벨 1개만 허용). 기존 합의 우선: PB 텔레그램 중립 평서체(`~다/~함`), HF 공식 산출물 냉정 단문.
- **길이**: 상단 3칸 합계 ≤10줄(하위 불릿 포함, 칸당 1~4줄), 1줄 ≤90자. 연구 요약본 전체 ≤60줄. 넘는 내용은 원본으로.
- **숫자 표기**: 상단 첫 줄 또는 머리에 `기준 YYYY-MM-DD HH:MM KST` 1회 + 출처(파일·기관). 자체연구·모델 숫자엔 등급 꼬리표 `(A)`·`(C)`·`(F)`·`(검증전)` 필수, 시장 관측치는 불요. `%`와 `%p` 구분, 부호 명시(+/−), 천단위 콤마, 표본 수 `n` 병기.
- **미확인 표기**: `미확인(무엇·확인 경로)` · `추정[가정: …]` · `데이터 없음(원인)` · `검증전`. 빈칸·생략으로 대체 금지.
- **3줄형 (텔레그램·알림 상단·화면 카드)**: 아래 3줄 + 원본 1줄. 텔레그램 본문은 그 아래(4절 8줄·운용회의 v2 25줄 상한 유지).
  - `① What: …` / `② So What: …` / `③ Now What: …` / `원본: <경로>`
- **예시** (샘플 v3 → 3줄형, 기준 2026-10-16 · reports/studies/accum_signals.md)
  - ① What: 매집 신호 8종 중 연기금 20일 순매수 상위 10%만 유의(A, 60일 초과수익 +5.41%, t 3.61)
  - ② So What: 외인·기관 매집 선행성 불충분(6종 무효·미약), 소형주 편중·거래비용 미반영
  - ③ Now What: 실계좌 적용 불가 · 관심종목 편입(관찰용) · 소형주 제외·비용 반영 재검증(퀀트)
  - 원본: reports/studies/accum_signals.md · 요약본 docs/desk_kb/report_format_sample_v3.md

- **제목·첫 줄·시각화 (11/1 겸이 「제목도 너무 길고 내용도 비직관적, 차트 그래프 표 등 활용하고 제목 직관적으로」):** ① 제목 18자 이내 질문형·결론형('반도체 수출, 정점인가?') — 데스크명·기준일·'매매 권고 아님'은 제목 말고 머리말 줄로 ② 파일 맨 위 `<!-- short: … -->`(서고 카드 제목) · `<!-- oneliner: … -->`(60자 결론, 숫자 1~2개) · 있으면 `<!-- kpi: … -->` ③ 숫자 3개 이상 비교는 표, 시계열·분포·순위는 ```chart``` 블록(서고가 SVG로 그림 — 형식: {"type":"bar|line|hbar","title","labels","series":[{"name","data"}],"unit","note"}) ④ 기호(①→≥·)는 표 밖 문장에서 최소화.

## 9. 문장 교정 규칙 (10/28 겸이 "규칙만 옮겨" — 출처 SolarLLM/human-proofreader-mcp(MIT) README, 외부 전송 없이 `scripts/proofcheck.py`)
- 고칠 이유를 한 문장으로 못 대면 고치지 않는다 · 덧붙이기보다 줄이기(길이 +5% 넘으면 경고).
- 사실 고정: 원문에 없는 숫자·문장이 생기면 차단 · 인용(따옴표)·고정 문장은 그대로.
- 말투 유지: 평서(~다/~함) ↔ 존대(~습니다) 전환 차단.
- 변경률 50% 이상 = 교정이 아니라 재작성(차단), 30~50% 경고 · 문장 합치기·쪼개기 과다 경고 · 상투어 추가 경고.
- 진단(`proofcheck.py read`): 60자 이상 긴 문장·번역투(~에 있어서·~을 통해·~에 대한·~으로 인해)·이중 피동(~되어지다·보여지다)·상투어(귀추가 주목·패러다임 등). 점수는 참고값(검증 전).
- 대조(`proofcheck.py compare 원문 교정본 [--keep 문장]`): 차단 있으면 종료코드 2. 비공개 글도 로컬에서만 돌아가므로 사용 가능.

## 10. 결재 안건 카드 (11/3 겸이 「안건 잘 정리해서 보고하는 법 리서치하고 그대로 적용해봐」 — 근거: BLUF(미 육군 AR 25-50)·SCQA/피라미드(민토)·board paper(결정 요청·옵션·권고·리스크)·RAPID/DACI(결정자 1명)·ADR(상태·결과·대체)·품의서(기안·합의·결재))
- **적용**: 오너 결재가 필요한 모든 안건(데스크·PB·라운드 출처 무관). 한 안건 = 폰 1화면(≤14줄, 1줄 ≤90자). 상세는 원본 링크로.
- **칸 정의** (순서 고정, 칸 삭제 금지 — 비면 `해당 없음(사유)`)
  - ① 결정 요청: 예/아니오로 답할 수 있는 한 줄 질문(BLUF — 첫 줄에 결론).
  - ② 권고안 + 대안 1~2개: 권고에 `(기본값)` 표기, 무응답 시 적용되는 상태도 명시.
  - ③ 왜 지금: 기한(M/D) + 안 하면 드는 비용 1줄.
  - ④ 근거 숫자 2개: 각각 출처 파일·기준일, 자체 숫자는 등급·`검증전` 꼬리표(8절 숫자 표기).
  - ⑤ 피어 반대 3줄: 피어리뷰 원문 발췌(가장 약한 가정·실패 시나리오·되돌림/선행 조건) + 파일 경로. **없으면 상정 불가** — 카드에 `피어 반대 미첨부 → 상정 보류`. 작성자가 대신 쓰지 않는다.
  - ⑥ 되돌림 조건: 언제·어떤 숫자면 원상 복구하는지.
  - ⑦ 결정 권한: 결정(1명) · 권고 · 입력 · 반대 · 집행 (RAPID/DACI).
  - ⑧ 답 키워드: `ㅇㅇ`=권고안 · `2`/`3`=대안 · `보류`. 한 글자로 답할 수 있게.
- **묶음 규칙**
  - 한 번에 최대 5건, 나머지는 대기열 표(안건·출처·기한·되돌림·막힌 이유).
  - 정렬: 기한 가까운 순 → 같으면 되돌리기 어려운 것 먼저. 같은 데스크·같은 원장 행은 1건으로 묶음(묶은 안건은 단위별 답 허용: `투자 ㅇㅇ`).
  - 카드 머리에 상태 1개: `🟢 상정` / `⏸ 상정 보류(사유)`.
  - 22:00~07:00 KST에는 규칙 변경 안건을 상정하지 않음. 밤에 답이 오면 🌙 기록만, 집행은 07:00 이후.
- **기록**: 답을 받으면 카드 번호를 인용해 결정 원장에 1줄(✅/보류), 카드는 대기열에서 삭제. 뒤집힌 결정은 원 행을 고치지 않고 새 행에 '○행 대체'(ADR 대체 규칙).
- **금지**: 공개 저장소에는 형식·규칙만. 실제 안건 내용·개인 금액은 비공개 저장소에 둔다.

## 11. 전략 연구소 가설 접수 (11/3 겸이 「모든 누나들의 영역이 전략연구소에 잘 반영되게」·「롱온리 편중 말고 기간도 유동적으로」)
- 모든 데스크는 자기 영역 가설을 전략 연구소에 넣을 수 있다: `scripts/ask.py --to 퀀트 --text "lab 가설: …"` 또는 `reports/lab_queue.json` 1객체. **필수 칸: 출처 데스크 · 방향(롱/숏/롱숏/중립/옵션/지수) · horizon(감쇠곡선|이벤트|고정) · 대상·데이터 경로 · 출처 파일.** 숏·롱숏·옵션은 실계좌 금지 기간엔 모의/HF 북 검증 전용(`real_eligible=false`). 사전등록·IS/OOS·다중검정·등급은 퀀트가 판정(kb:quant#33) — 데스크는 등급을 스스로 붙이지 않는다. 개인 금액·보유는 쓰지 않는다(필요하면 비율·'비공개 저장소 참조').
- 가설 재료: 전략 라이브러리 `docs/desk_kb/strategy_library/`(66장, 카드마다 방향·horizon 가설 칸 · 확인 태그 `[확인]/[2차]/[기억]`) — 인용 시 태그를 같이 쓴다.
