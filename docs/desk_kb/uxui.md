# UXUI 데스크 KB

UXUI = 터미널(apps-script 탭·텔레그램) 화면의 **정보 위계·가독성·조작성** 담당 — 겸이가 핵심 숫자를 **몇 초 만에 찾는가**를 재고 고칠 순서를 정한다(설계 → 프론트 구현 → UXUI 검수 — 10/24 프론트 신설 appr-staffing-30, 경계는 `front.md` ## 경계). 2026-10-21 신설(겸이 지시). 개인 보유·금액 없음. (2026-10-23 교육 정리: 작업 기록 압축.)

## 성격·성향

## 정의
- #1 [교과서] **정보 위계(information hierarchy)**: 화면 요소를 중요도 순으로 크기·위치·대비로 구분해, 시선이 '결론 → 근거 → 세부' 순으로 흐르게 하는 것. 측정: 핵심 숫자 탐색 시간(초), 첫 화면(390px 스크롤 없이) 안에 결론이 있는가.
- #2 [교과서] **가독성 기준**: 본문 대비 4.5:1 이상(WCAG 2.1 AA 1.4.3), 터치 대상 44px 이상(WCAG 2.5.5 권고·ui_smoke 기존 검사), 숫자는 같은 열에서 단위·소수 자릿수 통일.
- #4 [규정] **터치 대상 크기 두 기준**: WCAG 2.1 2.5.5(44×44px)는 **AAA**(권고 최고 단계), WCAG 2.2(2023) 2.5.8 '대상 크기(최소)' 24×24px 가 **AA**(실제 최저선, 간격으로 대신 가능). 차이: #2 는 44px 를 'AA급 기준'처럼 적었는데 실제로는 AAA. 우리 규칙 = 폰 주 조작(탭·목록 행)은 44px 목표, 24px 미만은 결함으로 본다.
- #3 [자체연구-검증전] **우리 화면 실패 사례(10/20~21 겸이 지적)**: 판단 성적표가 너무 길어 다른 걸 못 봄(→ 탭 분리) · 상단 지표 팝업 차트가 정적(→ 봉 단위 토글) · 공용 헤더 #fresh 배지 390px 에서 오른쪽 493px 까지 넘침(html,body overflow-x:hidden 이라 scrollWidth 검사로 안 잡힘 — 개발 D 보고 10/21).

## 인지 한계 근거표 (2026-10-28 학습 — 겸이 "가독성 좀더 … 학습좀")
> 입력은 겸이가 붙여넣은 GPT 정리(2차 자료)다. 원문(초록·출판 정보)을 웹 검색으로 대조해 판정했다. **확인** = 서지·핵심 수치가 원문 초록/저자 페이지와 일치. **부분** = 발견은 있으나 출처·수치 일부 불일치. **미확인** = 실존을 찾지 못함 → 우리 규칙의 근거로 쓰지 않는다. 이 세션에서 arxiv·sciencedirect·northwestern 본문 PDF는 네트워크 차단으로 못 열었다(검색 초록·저자 페이지 요약까지만 봄). 집계: 확인 8 · 부분 2 · 미확인 1.
