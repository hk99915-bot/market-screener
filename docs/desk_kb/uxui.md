## 정의
- #1 [교과서] **정보 위계(information hierarchy)**: 화면 요소를 중요도 순으로 크기·위치·대비로 구분해, 시선이 '결론 → 근거 → 세부' 순으로 흐르게 하는 것. 측정: 핵심 숫자 탐색 시간(초), 첫 화면(390px 스크롤 없이) 안에 결론이 있는가.
- #2 [교과서] **가독성 기준**: 본문 대비 4.5:1 이상(WCAG 2.1 AA 1.4.3), 터치 대상 44px 이상(WCAG 2.5.5 권고·ui_smoke 기존 검사), 숫자는 같은 열에서 단위·소수 자릿수 통일.
- #3 [자체연구-검증전] **우리 화면 실패 사례(10/20~21 겸이 지적)**: 판단 성적표가 너무 길어 다른 걸 못 봄(→ 탭 분리) · 상단 지표 팝업 차트가 정적(→ 봉 단위 토글) · 공용 헤더 #fresh 배지 390px 에서 오른쪽 493px 까지 넘침(html,body overflow-x:hidden 이라 scrollWidth 검사로 안 잡힘 — 개발 D 보고 10/21).

## 첫 업무 (보드 uxui-audit)
1. 탭 19개 × 390px·1300px 캡처(scripts/ui_smoke.py 재사용) → 탭별 점수: 위계·가독성·터치·일관성(색·숫자 표기·배지) 0~3점.
2. 고칠 것 Top 10(영향 × 빈도 ÷ 공수) → 겸이 결재 → 탭 1~2개씩 잠금 걸고 개발 구현 → UXUI 검수.
3. 공통 디자인 규칙 문서(색 토큰·글자 크기 단계·숫자 표기·배지 문법) 초안.
평가 기준은 '예쁨'이 아니라 **핵심 숫자 탐색 시간**과 **첫 화면 결론 유무**.
