# PM 데스크 KB

PM = 팀이 **얼마나·어디에** 일하는지 숫자로 보여주는 계기판 데스크(업무량·병목). 개인 보유·금액 없음. (2026-10-23 교육 정리: 성격·요금제 메모 압축.)

## 성격·성향
- **한 줄:** 하루에 많이 지은 것을 성과가 아니라 경고로 읽는 병목 측정자. "측정 자체가 병목에 먹혔다."(TH:pm §3)
- **맹점:** 팀 업무량 갱신 0건 — 소유자 불명의 수작업으로 둠(복기 10/17). **긴장:** ↔PB — 요청 전부 수락. 원본 [PERSONAS.md#pm](PERSONAS.md#pm)(요약, 연기 지시 아님).

## 정의
- **팀 업무량**: `ops/team.json` → SYSTEM 탭 '팀 업무량' 표(`apps-script/tab_system.html` sysTeamHtml).
  - `runs` = 에이전트 완료 통계 1건 1줄 `{date, owner, task, tools(도구 호출 수), sec(소요 초), tokens(처리 토큰)}`. 수작업 — 저장소에서 자동으로 얻을 수 없는 숫자.
  - `auto` = `scripts/team_stats.py` 자동 집계: 최근 7일 데스크별 커밋 수(커밋 메시지 매핑표 `COMMIT_RULES`, 봇 제외·미분류 별도), 보드 상태별 건수(owner), 라운드 참여 수, 받은 미처리 요청 수(`rounds/_requests.json`), 감사 치명/중/경(`reports/audit/*.json` by_desk, 7일).
  - `updated` = 마지막 집계 시각(KST). 화면은 날짜가 오늘이 아니면 '⚠ 갱신 안 됨 (n일)' 빨간 표시. `python3 scripts/team_stats.py --check` 는 같은 조건에서 종료코드 1.
- **요금제·모델별**(오너 10/17): `plans` 타임라인 `[{plan, from, to}]` — 전환일 미확인이면 `미지정`으로 묶음 [확인 필요: Pro→Max 5x 전환일(오너), 2026-11-15]. `by_plan`·`by_model` = 실행 수·토큰·도구·초 합계. 토큰 = 처리 작업량이지 요금제 한도가 아니다.
- **owner 이름** = 보드 담당 이름(PB·개발·퀀트·리스크 …). 영문 키(dev·frm)·별칭(팀장(PB)·FRM)은 스크립트가 보드 이름으로 바꾼다.

## 책임 (2026-10-17 오너 지시: "팀 업무량 최신화 — PM 일로")
- **runs**: PB가 에이전트 완료 통계(토큰/도구/초)를 PM에 넘기면 PM이 그날 안에 한 줄씩 추가. 진행 중 작업은 끝난 뒤에만.
- **auto**: 사람 손 없음 — `.github/workflows/ops.yml`(23:47·00:07 KST) + `scripts/round_collect.py --apply` 끝에서 호출. 실패 시 워크플로 경고 + 화면 ⚠.
- **점검**: 화면에 ⚠ 가 뜨면 PM이 원인(워크플로 실패·스크립트 오류)을 보드 태스크로 올린다. 미분류 커밋이 전체 사람 커밋의 절반을 넘으면 매핑표를 넓힌다.
- 영향 범위: ops/team.json · SYSTEM 탭 팀 업무량 표만. 롤백 = ops.yml 단계·round_collect 호출 제거(수작업 runs 는 그대로 남음).

## 한계 (검증전)
- 7일 커밋 수는 **커밋 메시지 접두**로만 귀속한다. 10/17 기준 사람·에이전트 커밋 380건 중 약 2/3 가 접두가 없어 미분류 [자체연구-검증전: team_stats 첫 실행 10/17]. 커밋 수 ≠ 업무량 — 토큰·도구(runs)와 같이 본다.
- ops.yml 저장 단계는 `pull --rebase -X theirs` 라, 같은 줄을 동시에 고치면 봇 쪽이 이긴다. runs 추가와 auto 갱신은 서로 다른 블록이라 보통 충돌 없음.
