# 정의·공식 (VaR·ES·스트레스·베타·분산·사이징)

(원본: docs/desk_kb/frm.md 해당 절을 그대로 옮김 — 2026-10-31 스킬 시범. 내용 수정은 KB 먼저, 이 파일은 같이.)

## 정의
- #1 [교과서] 손실 비대칭: 손실 L 뒤 원금 회복에 필요한 수익률 = 1/(1−L) − 1. −10% → +11.1%, −20% → +25%, −50% → +100%, −58% → +138%. (출처: CFA L1 Portfolio Risk & Return I, 산술·기하 수익률)
- #4 [교과서] 파라메트릭 VaR99 = 2.326σ, ES97.5 = 2.338σ (정규 가정, 1일, σ = 일간 수익률 표준편차). 정규면 둘이 거의 같다. (출처: Jorion *Value at Risk* 3판 5장 `[확인 필요: 원문 대조, 2026-10-30]`; BCBS FRTB)
- #5 [교과서] 역사적 VaR99 = 최근 250일 손익의 1% 분위; 역사적 ES97.5 = 최악 2.5%(약 6일)의 평균. 파라메트릭과 격차가 크면 꼬리가 두껍다는 신호. (출처: Jorion 5장 `[확인 필요: 원문 대조, 2026-10-30]`)
- #7 [현업 관행] 계기판 vs 한도: 계기판 = 보고 행동을 고르는 숫자(VaR·ES·β). 한도 = 초과 시 ①치유 기간 ②단계적 조치 ③예외 사전승인이 붙은 숫자. 셋 중 하나라도 없으면 보고 항목이다. (근거: 은행 시장리스크 한도 체계의 초과→치유→에스컬레이션 3단계)
- #9 [교과서] 스트레스 테스트(사건 재생) = 과거 특정 구간의 실측 수익률을 현재 비중에 적용한 손익률. 사건 선택: 내 주 위험이 터진 사건 + 성격이 다른 2~3개(유동성 위기형·하루 급락형·테마 붕괴형). (출처: Jorion 스트레스 테스트 장 `[확인 필요: 원문 대조, 2026-10-30]`)
- #11 [교과서] 베타 β = Cov(포트, 지수) ÷ Var(지수). 평균 관계이지 꼬리 보장이 아니다 — 테마 급락은 지수와 무관하게 더 깊을 수 있다. (출처: CFA L1 CAPM)
- #21 [규정] Basel FRTB(2016/2019)가 VaR99 → ES97.5로 간 이유: 임계값 '넘었는지'가 아니라 넘었을 때 '얼마나'(꼬리 평균)를 보기 위해. 97.5%는 정규에서 VaR99와 등가(2.338σ vs 2.326σ)라 보수성 수준은 유지, 두꺼운 꼬리에서만 ES가 더 커진다. 스트레스 ES = 최악 250일 구간 보정. (출처: BCBS FRTB, 2차 자료로 확인 `[확인 필요: 원문 절, 2026-10-30]`)
- #25 [규정] BCBS *Stress testing principles* (2018-10-17 발행, 2009년 원칙 대체, 원칙 1~9): 스트레스 테스트는 ①목적이 명시된 프로그램 ②거버넌스(승인·한도 연결) ③**시나리오는 '심각하되 개연성'(severe but plausible)** ④모형·가정 문서화 ⑤결과를 의사결정(한도·비중)에 실제로 쓴다 ⑥정기 검토. 우리 적용: 사건 재생(#9)은 '개연성'을 실측으로 충족, 한도 연결은 결재 #3(−15% 구속). 가정 문서화 — 2026-07 분류별 충격을 `pb.py STRESS_SCENARIOS` 주석에 적음(10/17 대리 −30 → 10/24 결재로 실측 semi −50 · elec −60 · 코어 바구니 실측 교체, 원천·구간 병기). (출처: BIS d450 press release p181017 2차 확인 `[확인 필요: 원칙 번호·문구, 2026-10-24까지 d450.pdf 원문 대조]`; 반대 근거: 은행용 원칙이라 개인 포트엔 '감독당국' 절반은 무관 — 적용 범위는 ①③⑤만)

- #26 [규정] FRTB 스트레스 기간 선택: 스트레스 ES의 기간은 '시장 전체가 최악인 기간'이 아니라 **현재 포트폴리오에 최악인 12개월 구간**(2007년 이후 관측에서 탐색)을 고른다 — 포트가 바뀌면 스트레스 기간도 바뀐다. 우리 적용: 사건 재생(#9)의 구간을 지수 창이 아니라 '사건 범위 안 현재 포트 경로의 최대 낙폭 t0<t1'로 잡는다. 2026-07 실측: 엔진 지수 창(06/30 시작)은 코스피 −34.0%, 실제 고점→저점 06/22→07/30은 −38.6%, 개인 북 재생 −0.6%p 차(비율만, reports/studies/2026-10-23_frm_replay_2026-07.md). (출처: BCBS FRTB 2019 MAR33 스트레스 기간 조항, 2차 자료로 확인 `[확인 필요: 조항 번호·'12개월'·'2007년 이후' 문구, 2026-10-30까지 원문 대조]`; 반대 근거: 은행은 12개월 ES, 우리는 단일 사건 누적 손실이라 기간 길이는 다르다 — 원리(포트 기준 선택)만 가져온다)


## 공식
- #2 [교과서] 산술 vs 기하: +50% 뒤 −50% → 산술평균 0%, 실제 100→150→75 (2년 −25%, 연 −13.4%). (출처: CFA L1)
- #3 [교과서] 변동성 끌림: g ≈ μ − σ²/2. σ 20% → −2%p, σ 40% → −8%p — σ 2배면 끌림 4배. μ 5%·σ 40%면 g ≈ −3%(산술 양수, 복리 음수). Kelly 성장률 g(f) = μf − σ²f²/2의 f=1 경우. (출처: Kelly 성장률, 2차 자료로 확인 `[확인 필요: 원전, 2026-10-30]`)
- #6 [교과서][규정] 초과일 백테스트: 매일 "손실 > 전날 VaR99?" 카운트. 250일 기대 2.5회. Basel 신호등: 0–4 녹(정상) / 5–9 황(의심) / 10+ 적(모형 폐기). 초과일이 몰려 있으면 레짐 변화, 고르게 흩어져 있으면 모형(꼬리) 오류. 0회도 오류(VaR 과대 → 비중 불필요 축소). (출처: Jorion 3판 6장 Kupiec POF·Christoffersen `[확인 필요: 원문 대조, 2026-10-30]`; Basel 백테스트 `[확인 필요: 원문 대조, 2026-10-30]`)
- #10 [산술] 스트레스 비중 산술: 포트 손실 = 충격 × 비중. −15% × 40% = −6%. 한도 −15%면 허용 충격 = 15 ÷ 비중(40% → −37.5%). 테마 재생 충격이 −45%면 비중 ≤ 33%. 구속 시나리오 2026-07 실측(반도체 −50%, 10/24 결재) → 반도체 단독 허용 비중 ≤ 30%(옛 대리 −30%면 50%) — 코어·전기 손실이 같은 −15%를 나눠 쓰므로 실제 여유는 더 작다. (출처: 정의에서 직접)
- #12 [교과서] 2자산 분산 σ_p² = w₁²σ₁² + w₂²σ₂² + 2w₁w₂ρσ₁σ₂. 각 σ 40%, 50/50: ρ 0 → 28.3%, 0.5 → 34.6%, 0.8 → 38.0%, 0.9 → 39.0%, 1 → 40%. n종목 등가중·동일 ρ: σ_p²/σ² = 1/n + ρ(1−1/n); ρ 0.8·n 5 → σ_p = 0.92σ. (출처: CFA L1 Portfolio Risk & Return II)
- #15 [산술] 현금흐름 리밸런싱(적립 희석): w′ = w(1+r) / (1 + c + w·r). w 테마 비중, r 테마 수익률(기타 자산 0), c = 적립 ÷ 직전 순자산(기타 자산에 투입). r=0 → w′ = w/(1+c): 40%·c 2%/월 → 7개월에 35%(0.4/1.02⁷ = 0.348); c 13.7%면 1개월에 35.2%. c 분모(직전 vs 시작 순자산)를 먼저 정의할 것. (출처: 비중 정의에서 유도; semis_cap H2 사전 산술과 일치)
- #16 [현업 관행] 포지션 사이징: 비중 = 1회 리스크 예산 ÷ 손절폭. 1% ÷ 8% = 12.5%; 손절폭 6% → 16.7%; 12% → 8.3%. 손절 = max(20일 저점, 종가 − 2×ATR14), 최소 1×ATR. (근거: 트레이딩 데스크 'R 단위' 사이징; 자체연구 rule_audit #6 atr_stop 등급 C)
- #24 [교과서] 위험 기여(성분 VaR 비율) = w_i × Cov(r_i, r_p) / σ_p². 50/50, σ 40%·10%, ρ 0 → 기여 94% vs 6%(비중 같아도 위험 16배 차이). 성분 VaR 합 = 포트 VaR(단독 VaR 합보다 작다). (출처: Jorion 3판 7장 marginal/component VaR `[확인 필요: 원문 대조, 2026-10-30]`)
